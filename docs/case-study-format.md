# GMBF Ventures case-study format

Use this guide for every new or revised case study. Each case study is a sales page with a companion two-page PDF. Use Digital Snagging as the visual reference for both. Start with the buyer's problem and show what GMBF can help them do.

## Web page

Use the layout and shared components of [Digital Snagging](../src/site/case-studies/digital-snagging.html).

1. **Hero.** Use a short title that names the buyer's task. Add one sentence on the value, a compact project summary with the project stage, and a visible **Download the 2-page PDF** button.
2. **About this case study.** State the evidence and status in one short note. Use clear wording for prototypes, demonstrations with sample data and completed client work.
3. **The problem.** Name who experiences it, what slows them down and what is at stake. Use publishable project detail and quantities where they make the problem tangible.
4. **The approach.** Explain what GMBF scoped, built or delivered and why. Include a workflow diagram or another visual that makes the approach easy to follow.
5. **How it works.** Show the workflow with approved screenshots, a diagram or a clearly labelled illustrative example. Show the action, the evidence produced and the decision or handoff.
6. **What it is designed to change.** Give three or four concrete benefits a buyer can recognise. Use measured figures only where evidence supports them. State what a pilot would test when the work is at prototype stage.
7. **Apply this to your projects.** Use one main call to action for the relevant service and name what the buyer can discuss or commission. Place any supporting sources before this call to action.

## Downloadable PDF

Use the [Digital Snagging PDF](../src/site/assets/downloads/gmbf-case-study-digital-snagging.pdf) as the design reference. Match its two-page A4 layout, dark hero, lime accent, section labels, cards and numbered footer.

- **Page 1** carries the headline, one-sentence value proposition, the problem, the approach, a workflow visual and a short project-status note.
- **Page 2** shows how the workflow works, the intended or evidenced benefits, and a clear way to enquire. Use approved screenshots or a labelled illustration as appropriate.
- Keep the page and the PDF aligned on facts, delivery stage and contact route. Save the PDF in `src/site/assets/downloads/` alongside the other case-study PDFs and link it from the hero.

## Before review

- Check claims against project evidence. Confirm client references, screenshots and document excerpts are cleared for publication.
- Check the Case Studies listing, category, related service link and sitemap entry. Confirm the hero download opens the correct PDF and the enquiry link goes to the intended route.
- Read both PDF pages at full size and verify the web layout on desktop and mobile. Run the site tests and build before submitting the GitHub pull request.
